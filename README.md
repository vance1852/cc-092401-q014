# 人形机器人试验统计准入服务

本仓库是一套已经实现并可直接运行的服务端项目，用于把人形机器人在递送、讲解和灵巧操作等场景中的结构化试验记录转成可复核的统计准入结论。系统以 SQLite 保存组织、团队、成员关系、机器人、软件构建、不可变协议版本、试验批次、原始观测、排除申请、分析快照、准入决定和审计事件，不依赖机器人设备、图片、音频、视频或外部基础设施。

## 多组织与多团队模型

同一套服务可供多个事业部（组织）共用，隔离规则如下：

- **组织（organization）与团队（team）**：机器人、构建、协议和批次都必须归属一个组织下的一个团队；批次引用的协议与构建必须在同一组织、同一团队内，跨组织或跨团队关联在服务层与数据库外键两层都会被拒绝。
- **按团队授予的角色**：`operator`、`statistician`、`approver`、`auditor` 仍然职责分离，但只在被授予的团队内生效。同一用户可以在 A 团队是操作员、在 B 团队是统计负责人；每个团队内每用户只能有一个角色。
- **组织级角色**：`org_admin` 只能创建团队、授予或撤销成员关系，没有任何业务审批权（不能封存批次、不能审批结论）；`org_auditor` 可在本组织内跨团队只读批次、目录和报告，看不到其他组织，也不能写入。
- **撤权即时生效**：成员关系被撤销或用户被停用后，下一个请求立即失权。所有写操作都在 `BEGIN IMMEDIATE` 事务内完成"鉴权 → 并发屏障 → 成员关系二次确认 → 写入"，配合 SQLite 写事务串行化，杜绝"权限检查后被撤权仍写入"。
- **历史身份冻结**：审计事件额外记录 `actor_role`（以及 `org_id`/`team_id`），成员事后被移除不改变历史报告中显示的当时身份。
- **无存在性侧信道**：对象编号（机器人、构建、批次、协议）在团队范围内唯一，跨团队/跨组织重名互不冲突也无法通过"编号已占用"互相探测；列表对无权过滤条件返回空集合；单项读取、报告对不可见对象一律返回与"不存在"完全相同的 404；写入时引用他人对象与引用不存在对象返回相同错误。

现有代码按职责分为：

- `api.py`：标准库实现的 HTTP JSON 接口与无网络路由测试边界；
- `service.py`：组织/团队鉴权、角色权限、批次状态机、幂等导入、排除复核、任务租约、审批和报告；
- `analysis.py`：分层覆盖、Wilson 区间、描述性统计、确定性 bootstrap 和准入规则；
- `contracts.py`：协议、指标、分层、权重、随机种子和单次观测的数据契约；
- `jsonio.py`：严格 JSON/JSONL 读取、规范化序列化与内容摘要；
- `numeric.py`：不依赖第三方库的描述性统计和 Wilson 区间；
- `storage.py`：完整 SQLite 业务模式（复合外键、范围唯一约束、索引）和事务辅助；
- `clock.py`：生产时钟与可确定性推进的测试时钟；
- `acceptance.py`：贯通建档、导入、封存、分析、审批和报告的离线验收。

系统已经实现以下主流程：协议发布后不可原地覆盖；批次按版本从草稿进入运行、封存、分析和决定状态；观测分片同时受请求幂等键和来源行唯一身份保护；排除请求必须由不同角色复核；分析任务使用 SQLite 租约避免重复执行并支持过期接管；同一输入快照使用固定算法版本和随机种子得到一致结果；分析者与审批人职责分离，报告保留输入摘要、统计规则和批次审计链。

## 环境

- Linux
- Python 3.11 或更高版本
- 无需安装第三方 Python 包

如需安装到隔离环境，可在依赖已经准备好的容器中执行：

```bash
python3 -m pip install --no-index --no-deps .
```

## 测试

在 `project/` 目录执行：

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

测试使用临时目录和内存数据库，不访问网络，也不依赖常驻服务。其中 `tests/test_multitenancy.py` 覆盖跨团队/跨组织隔离、组织审计员只读、撤权即时生效、并发撤权与封存/审批的事务竞争，以及 HTTP 存在性侧信道防护。

## 构建检查

本项目是纯 Python 源码包，构建检查采用字节码编译：

```bash
python3 -m compileall -q src tests
```

## 无浏览器验收

下面的命令会读取 `fixtures/` 中的协议与观测记录，在临时 SQLite 数据库中完成组织与团队建档、成员授权、设备建档、协议发布、批次启动、观测导入、批次封存、任务领取、统计分析、准入审批以及团队审计员和组织审计员报告导出，随后输出一行 JSON 结果：

```bash
PYTHONPATH=src python3 -m robot_trials.acceptance --workspace .
```

成功时退出码为 `0`，输出中的 `status` 为 `ok`。验收过程不会写入仓库，也不需要浏览器或外部服务。

## 启动 HTTP 服务

```bash
PYTHONPATH=src python3 -m robot_trials.api --database robot_trials.sqlite3 --host 127.0.0.1 --port 8080
```

接口使用 `X-Actor-Id` 表示当前操作人，写入观测时还需提供 `Idempotency-Key`。

### 初始化顺序

1. `POST /users` 创建用户（不带角色）；
2. `POST /organizations` 创建组织并指定首任 `org_admin`；
3. 组织管理员调用 `POST /organizations/{org_id}/teams` 创建团队；
4. 组织管理员通过 `POST /memberships` 向团队授予 `operator`/`statistician`/`approver`/`auditor`，或授予组织级 `org_auditor`；
5. 团队操作员登记机器人与构建、团队统计负责人发布协议，之后即可启动批次并导入观测。

所有团队内写入请求都必须在 JSON 体中携带 `org_id` 与 `team_id`；列表接口可用 `?org_id=...&team_id=...` 过滤，对无权范围一律返回空数组。单项读取与报告只通过对象编号访问，服务端按调用方的可见范围解析，不可见对象与不存在对象返回完全相同的 404。

服务进程可以停止后重新启动，SQLite 中的业务状态、分析任务和租约信息会保留。
